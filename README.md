# Otago Property Explorer — v4

تطبيق GIS محلي لاستكشاف العقارات والقطع والطرق في Otago باستخدام ArcGIS Maps SDK for JavaScript، مع تحليلات مكانية وقياسات وتصدير النتائج.

## 1. التشغيل

1. ثبّت Node.js إصدار 18 أو أحدث.
2. فك ضغط المشروع داخل مجلد مستقل.
3. افتح PowerShell أو Terminal داخل المجلد.
4. نفّذ:

   ```powershell
   npm start
   ```

5. افتح `http://localhost:3000`.

يحتاج التطبيق إلى اتصال بالإنترنت لتحميل ArcGIS Maps SDK وخدمات بيانات ORC ومكتبة قراءة Shapefile. الخادم المحلي يستمع إلى `127.0.0.1` فقط، ويحفظ التحليلات في `storage/saved-analyses.json`.

## 2. أهم الوظائف

- اختيار المنطقة الإدارية والمحلية والشارع، ثم تحليل القطع في نطاق طريق محدد.
- رفع Shapefile مضغوط بصيغة ZIP يحتوي على ملفات الطبقة اللازمة. تُعرض جميع تسميات الأضلاع الفريدة لملف Shapefile افتراضيًا على الخريطة. يمكن تعطيلها من خيار «إظهار أطوال جميع أضلاع Shapefile على الخريطة» إذا ازدحمت الخريطة. تتاح قائمة تفاعلية بجميع الأطوال من تبويب Shapefile.
- تحديد أي قطعة من الخريطة وحساب المساحة والمحيط وأطوال الأضلاع.
- مقارنة القطعة بالطبقة المقابلة وعرض مساحة التقاطع ونسبة التداخل من مساحة القطعة والعنصر المقابل.
- حساب المسافة الهندسية إلى أقرب شارع مرشح ورسم الشارع وخط القياس ونقطتي النهاية. إذا وصل استعلام الطرق إلى حد نتائجه، تظهر ملاحظة تمنع اعتبار المسافة مؤكدة دون مراجعة.
- رسم نقطة أو خط أو مضلع أو مستطيل أو دائرة باستخدام Sketch، وعرض الإحداثيات في `EPSG:4326` و`EPSG:2193`. المضلع المرسوم يشغّل تحليل التقاطع مع طبقتي ORC Properties وLINZ Primary Parcels.
- لوحة تحليل واحدة قابلة للسحب تحتوي تبويبات «القطعة» و«التقاطع» و«Shapefile»؛ لا تظهر التبويبات التي لا تحتوي على نتائج.
- أدوات الأبعاد اليدوية وتحويل الإحداثيات وإنشاء الأشكال من النقاط اليدوية داخل قسم متقدم لتقليل ازدحام الواجهة. القيم اليدوية توثيقية وليست قياسات محسوبة تلقائيًا.
- حفظ النتائج عبر Backend وتنزيل نسخة JSON، أو تصدير CSV مع حماية القيم النصية التي قد تُفسّر كصيغ Excel. زر التقرير ينشئ تقرير طباعة يتضمن لقطة للخريطة وملاحظات جودة النتائج؛ من نافذة التقرير اختر Print ثم Save as PDF لحفظه كملف PDF. عند تعذر لقطة الخريطة يستمر إنشاء التقرير ويذكر ذلك بوضوح.

## 3. نظام الإحداثيات ودقة القياسات

تُجرى المساحات والأطوال والمسافات المترية على هندسات محوّلة إلى `EPSG:2193` (NZGD2000 / New Zealand Transverse Mercator)، والوحدات هي المتر والمتر المربع.

مكتبة `shpjs` تعيد عادةً بيانات الملفات ذات تعريف إسقاط قابل للقراءة إلى إحداثيات جغرافية؛ لذلك يتحقق التطبيق من نطاق الإحداثيات قبل اختيار التحويل. إذا بدت الإحداثيات مسقطة ولم تطابق النطاق المتوقع لـ NZTM، يوقف التطبيق التحليل ويطلب إرفاق ملف `.prj` الصحيح أو إعادة إسقاط البيانات بدل افتراض نظام إحداثيات غير مؤكد.

**حدود مهمة:** معرفة نظام إحداثيات صحيح لا تكفي وحدها لضمان صلاحية هندسة تالفة أو وجود كل النتائج من الخدمة. يوضح التطبيق عند بلوغ حد الاستعلام، وقد يقتصر تقرير الطباعة على أول 250 نتيجة لتجنّب تقرير ضخم؛ تصدير CSV يشمل قائمة النتائج كلها.

## 4. فحوصات المشروع

لفحص صياغة ملفات JavaScript:

```powershell
npm run check
```

لتشغيل اختبارات الوحدة الثابتة:

```powershell
npm test
```

تختبر هذه الأوامر سلامة الصياغة، وتفرّد معرّفات HTML ومراجع عناصر الواجهة، وحساب أطوال أضلاع اختبارية وترتيب أطول الأضلاع، وترقيم استعلامات النتائج والتعامل مع حد النتائج، وإظهار أطوال الأضلاع الفريدة من دون تكرار الضلع المشترك، والتحقق من أسماء نسب التقاطع، وحماية قيم CSV من صيغ الجداول، وتضمين لقطة الخريطة وتحذيرات النقص داخل التقرير.

هذه الاختبارات لا تستبدل الاختبار التشغيلي عبر متصفح متصل بخدمات ArcGIS؛ يجب مراجعة النتائج المكانية على ملف Shapefile معروف المساحة والأطوال قبل اعتمادها مهنيًا.

## 5. بنية الملفات

- `index.html`: عناصر الواجهة.
- `styles.css`: الأنماط والاستجابة لحجم الشاشة.
- `js/app.js`: تهيئة الخريطة وربط أدوات التحليل واستخدام الخدمات.
- `js/geometry-service.js`: أطوال الأضلاع وتسميات القياس الهندسية.
- `js/data-service.js`: استعلامات الطبقات والصفحات وحد النتائج.
- `js/popup-service.js`: تفاصيل العنصر والنوافذ المنبثقة.
- `js/export-service.js`: حفظ JSON وتصدير CSV وتقرير الطباعة.
- `js/shapefile-loader.js`: تحميل محلل Shapefile.
- `js/config.js`: روابط الخدمات وإعدادات نظام الإحداثيات.
- `server.js`: الخادم المحلي وواجهات الحفظ.
- `tests/smoke.test.js`: اختبارات الوحدة والفحوصات الثابتة.

## 6. السلامة التشغيلية

- لا تعتمد على النسب أو المسافات إذا ظهر تحذير بأن الاستعلام بلغ حد النتائج.
- قبل استخدام ملف Shapefile في تقرير رسمي، قارن نتائج مساحة ومحيط معروفة بالمصدر الأصلي.
- ملف `storage/saved-analyses.json` يحتفظ بالسجلات السابقة؛ احتفظ بنسخة احتياطية قبل نقل المشروع أو تغيير التخزين.


## تحديث v4
- إظهار نسب التقاطع تلقائيًا بعد إنهاء رسم مضلع باستخدام Sketch، مع تسميات عربية واضحة على الخريطة وداخل الملخص.
- تفعيل إظهار أطوال جميع أضلاع Shapefile افتراضيًا، مع إمكانية إخفاء معظم التسميات من الخيار المخصص. قد تتقارب التسميات في الأشكال الكثيفة؛ يمكن التكبير أو إخفاء التسميات مؤقتًا.
- إزالة زر تقرير PDF وربط وظيفة التقرير من الواجهة. التصدير المتاح حاليًا JSON وCSV.
- شرح معنى النسبتين: نسبة مساحة التقاطع من مساحة عنصر الطبقة، ونسبة مساحة التقاطع من مساحة الرسم/ملف Shapefile.
